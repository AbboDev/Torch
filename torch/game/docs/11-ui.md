# UI panels and widgets

Retained interface widgets on the screen layer: panels and windows with flex
layout, labels, buttons, toggles, checkboxes, radios, sliders, progress bars,
text inputs, textareas, scrollable lists and dropdowns. Panels are roster objects
drawn by a rounded-box signed-distance shader — fill or gradient, rim, bevel
lit from a direction, gloss (cap, band, jelly pill or dome), glints, a shine that sweeps
across, a 3D lip the face presses down into, inner shadow, blurred drop shadow, per-corner
radii, tint, offset — with styles as data. Captions take a stroke of any width and an
extruded drop, like game text, and so do the engine's 125 icons. Labels use retained Typography paragraphs with font fallback and Unicode shaping. Buttons, toggles, sliders and progress bars are built from the
two, driven by the pointer, with hover, pressed and disabled looks.

## When to use it

Menus, HUD panels, settings, pause screens, shop and inventory frames. For
rich paragraphs, animated lettering or 3D labels, use `typography` directly; for full custom drawing, `render-texture`.
For glossy, chunky game-quality menus without writing styles, compose `ui-skins` and a skin pack after it
(`ui-skin-candy`, `ui-skin-jelly`, `ui-skin-glossy`, `ui-skin-bubble`, `ui-skin-block`, `ui-skin-cartoon`,
`ui-skin-wood`, `ui-skin-metal`, `ui-skin-bezel`, `ui-skin-candystripe`, `ui-skin-timber`) and set `game.ui.theme = 'candy'`: every widget, in one material and colour, from the
fields below. For a game's meters — health, timers, XP, ammo, loading, cooldown rings, a bar over each enemy — compose `bars`:
`game.bars.create({...})` is a styled, animated bar in one call. `progress` here is the plain widget for a menu's layout.

## Requires

`typography` composed before `ui`, a WebGPU or WebGL2 backend, and a screen-space layer (`world-screen`'s
`hud` by default). Headless the widgets exist, lay out and answer input.

## API

Fonts load on first use: a widget's caption appears when its style's font arrives, and the
widgets are measured and laid out again then. To have widget text on the first frame:

- Widgets made before `game.start()` need nothing: start waits for their fonts, and for the fonts of the theme
  chosen by then (`game.ui.theme = 'candy'` before the first load puts a skin's font under the loading screen).
- For widgets made later (in a scene's `enter`), `await game.ui.ready()` after making them waits for their fonts,
  or name the fonts first with `await game.typography.prepare(['sans-bold', 'sans'])`. The built-in styles use
  `sans-bold` (everything but `retro`) and `mono-bold` (`retro`); a theme names its own.

The host must serve the `/typography/` runtime assets; the shared UI fonts come from the Phaser AE CDN (see `typography`).

```ts
const win = game.ui.window({
  anchor: "center",
  w: 320,
  h: 240,
  title: "MAIN MENU",
  layout: { padding: 16, gap: 12, align: "stretch" },
});
game.ui.button({
  parent: win,
  h: 40,
  text: "PLAY",
  style: "good",
  onClick: () => game.scenes.go("play"),
}); // laid out by the window: no x/y needed
game.ui.button({ parent: win, h: 40, text: "OPTIONS" });
const row = game.ui.panel({
  parent: win,
  h: 34,
  style: { fill: "#00000000" },
  layout: { direction: "row", padding: 0, gap: 16, justify: "center" },
});
game.ui.toggle({ parent: row, w: 56, h: 28, text: "SFX", value: 1 });
const sfx = game.ui.toggle({
  anchor: "top-right",
  x: -16,
  y: 16,
  w: 56,
  h: 28,
  text: "SFX",
  value: 1,
  onChange: (v) => game.sound.volume("sfx", v),
});
game.ui.slider({
  anchor: "bottom",
  y: -24,
  w: 240,
  h: 22,
  value: 0.7,
  onChange: (v) => game.sound.volume("music", v),
});
const done = game.ui.progress({ parent: win, h: 14, style: "track" });
done.ui.value = 0.42; // in a layout; a game's health bar is the bars pack
game.ui.label({
  anchor: "top",
  y: 8,
  text: "LEVEL 3",
  style: { font: "bold 18px sans-serif", textColor: "#ffd166" },
});
game.ui.defineStyle("neon", {
  base: "glass",
  fill: "#3dd6ff33",
  borderColor: "#3dd6ff",
  gloss: 0,
  shadow: 0.9,
  shadowColor: "#3dd6ff",
  shadowBlur: 18,
});
```

- **Buttons fit their content.** A button given no width (or `w: 'auto'`) sizes itself to its icon, caption, caption
  stroke and padding, and again whenever they change; an icon alone makes it square. A button with a width — given,
  set later with `h.ui.w`, or stretched across a column by its layout — keeps it and shrinks its caption and icon
  together until they fit the face (never below 30%). A caption is never taller than the face either. So a button
  never has to be measured, and its content never spills over its edge. A label in a style drawn for a height (one
  with a `designHeight`, as a skin's `heading`) fits too: its caption grows with its height and shrinks to its width.
- `window(spec)` — a container with a title bar and a column layout (padding 16, gap 10, children centred). `panel` with a `layout` is a container too; containers nest (a row panel inside a column window).
- `checkbox({ text, value })`, `radio({ group, text, value })` — a ticked box, a grouped dot; `ui.change` with 0/1 on flip (a radio fires 1 on the one chosen and clears its group).
- `input({ value, placeholder, maxLength, password, onInput, onSubmit })` — a one-line field: click to focus (or `h.ui.focused = true`), type, Backspace/Delete, arrows, Home/End; Enter submits (`ui.submit`), Esc unfocuses; `ui.input` as it changes.
- `textarea({ rows, ... })` — the multi-line version: wraps, Enter breaks a line, Ctrl/⌘+Enter submits, the wheel scrolls by line, the caret is kept in view.
- `list({ options, rows, rowHeight, value, onChange })` — a scrollable list: the wheel scrolls by row, a click selects (`ui.change` with the index); `h.ui.options` replaces the items, `h.ui.scroll` the first visible row. The rows and scrollbar keep inside the list's frame, its `border` plus its `contentInset` (at least 4 px), so a list wearing a skin's wide rim is that much taller than its rows, and a theme with another frame refits a list built without a height.
- `dropdown({ options, value, rows })` — a button showing the choice; click opens a list under it, a pick or a click elsewhere closes it. The open list draws above its dropdown, inside a modal too, and goes when the dropdown is killed.
- `panel label button toggle slider progress (spec)` — spawn a widget (owner `ui`, tag `ui`); the returned handle's `ui` sub-object is the API.
- `slider` takes `min`, `max` and `step` as well as `value`. Without them it is the plain 0..1; with them
  `value` is the number the GAME means — difficulty 2, not 0.67 — and the track position is derived from it
  for drawing. A stepped slider snaps on drag and never reports a value off a step.
- Spec: `anchor x y w h layer z style text icon iconSize disabled hidden id parent layout bounce`; `toggle/slider/progress` take `value`; `button` takes `onClick`, the others `onChange`; `window` adds `title titleHeight titleStyle`.
- `parent` puts a widget inside a container. With a `layout` on the parent the widget is placed by it (`x y` become nudges, `anchor` is ignored); without, `anchor x y` are relative to the parent's content box. A child takes its parent's `layer` unless it names one. Hiding or killing a container hides or kills its children.
- A callback may kill its own widget, or its container: `onClick: () => kill(dialog)` closes the dialog and every button in it at once, and nothing touches the dead widgets afterwards.
- The pointer goes to the widget drawn on top: the later-drawn layer, then the higher `z`, then the widget made later. Panels and windows block it: a press on a panel or window does not reach a widget it covers, or the game world behind it, though the widgets on it (drawn above it) work as normal. Labels, progress bars and a panel with a transparent fill (a layout container) let it through, to the widgets and to the world. A disabled control on top takes nothing and blocks what is beneath it. The wheel and a list's scrollbar act on the top-most list or textarea under the pointer only.
- `layout`: `direction` ('column' | 'row'), `padding` (number or per side), `gap`, `align` ('start' | 'center' | 'end' | 'stretch' — stretch gives the child the content width/height), `justify` ('start' | 'center' | 'end' | 'space-between' | 'space-around'). CSS flexbox, one level at a time.
- `alignSelf` on a CHILD overrides the parent's `align` for that one widget — a column of stretched fields with one left-aligned caption.
- `w: 'auto'` on a row container, or `h: 'auto'` on a column one, sizes it to its visible children plus its padding and title bar, every frame. A hand-written height is the number that goes wrong the moment a control is added, and it goes wrong at the bottom edge.
- A **checkbox** or **radio** is a box plus a row: `w`/`h` are the clickable area — stretch one across a settings column and the whole line is one target — while the tick box stays a square, left-aligned in it, with the label beside the box.
- `bounce`: press feedback (the style's `pressed.offsetX/Y` sink). Default true for buttons only; toggles, sliders and everything else never move under the pointer.
- `h.ui`: `text style restyle() hover pressed disabled hidden value textValue focused scroll options group w h x y anchor onChange rect kind parent children layout relayout() content`.
- Signals per step: `ui.change { id, value }`, `ui.input { id, text }`, `ui.submit { id, text }`; `focus` is the focused interactive widget.
- `clip: true` on a container confines every descendant to its rectangle — panels **and** labels.
  A panel is clipped in the shader, per fragment, because the drawer packs every panel into one
  draw and a scissor would have to split it per rectangle. A label is a retained Typography paragraph
  in the native text pass; its shader clips paragraph-local geometry to the same rectangle. A container does not
  clip _itself_ — that would eat its own border. A descendant entirely outside stops drawing.
- `defineStyle(name, style)`, `styles`, `hot`, `widgets`. Defining a style name again replaces it (a built-in's
  too), live: every widget repaints and re-lays in the new definition, as for a theme switch, so styles defined in a
  scene's `enter` are safe when the scene runs again. An identical definition does nothing. A style the active theme
  also names is still drawn from the theme.
- Signal per step: `ui.change` `{ id, value }` (a button click is value 1).

### Icons, and the pause and sound buttons

A game never spells its buttons out ("II", "SND"): the engine has icons, and any widget shows one with `icon`.

```ts
game.ui.pauseButton(); // top right: opens the pause menu, the 'pause' scene, over play
game.ui.muteButton(); // beside it: sound on and off, following the sound however it was muted
game.ui.button({
  parent: menu,
  h: 56,
  text: "Restart",
  icon: "restart",
  onClick: () => game.scenes.go("play"),
});
game.ui.button({
  anchor: "top-left",
  x: 16,
  y: 16,
  h: 56,
  icon: "back",
  onClick: goBack,
}); // an icon alone: square
const note = game.spawn({
  texture: game.ui.icon("music-on"),
  layer: "hud",
  x: 40,
  y: 40,
  width: 24,
  height: 24,
  tint: "#ffd166",
});
```

- **The icons** (`game.ui.icons`, `UI_ICONS`, 125 of them). Play and sound: `pause play stop next previous fast-forward
rewind sound-on sound-off music-on music-off headphones microphone vibrate`. Menus: `home settings sliders menu more
close back arrow-left arrow-right arrow-up arrow-down caret-left caret-right caret-up caret-down restart undo redo
shuffle levels fullscreen fullscreen-exit exit sign-out`. Answers and edits: `check plus minus info question warning
lock unlock eye eye-off search edit save trash hint share`. Rewards and shop: `star star-half heart heart-break crown
trophy medal leaderboard chart coin coins gem gift package ticket key piggy-bank shop cart bag film like`. Play
  things: `lightning lightning-off fire snowflake drop leaf sparkle shield shield-check sword bomb potion skull ghost
robot rocket paw puzzle dice gamepad hammer wrench brush palette target crosshair flag map pin tap timer hourglass
clock calendar sun moon cloud`. People: `user users smiley chat chat-text mail bell globe book bookmark camera
video-camera`. Each is drawn white and takes the widget's caption colour (the style's
  `textColor`, with its hover, pressed and disabled looks), so a theme colours them with everything else.
- `icon` takes one of those names, or **any picture by name** (painted, or loaded from assets.json) when the game has
  its own art for the button: that shows as it is, and one from a pack still loading appears when it lands. With
  `text` the icon comes first and the two are centred together. `iconSize` is its size (default 60% of the widget's
  smaller side); `h.ui.icon` swaps it live, `null` takes it away. An icon-only button is named by its icon for
  screen readers ('Pause', 'Sound on') unless `accessibleLabel` says otherwise.
- An engine icon is drawn like the caption: the style's `textStroke` outlines it, `textDepth` extrudes it and
  `textShadowX/Y` lays a hard shadow under it (a light one just below debosses it into the face), each its silhouette
  grown and tinted on a sprite behind it. A game's own picture shows as it is.
- `game.ui.icon(name)` gives an icon as a picture by name, for a sprite of its own (a HUD symbol, a tutorial hint).
- **`pauseButton(spec)`**: a 56 px square with the pause icon, top right. A press opens the game's pause menu, the
  scene called `'pause'`, pushed over play (`game.scenes.push('pause')`): play is held beneath it while the menu runs
  and animates, and the menu's resume is `game.scenes.pop()`. It throws when there is no `'pause'` scene and no
  `onClick`. It is not `game.commands.pause()`, which holds the whole game, menu and all: that is the host's pause.
- **`muteButton(spec)`**: a 56 px square beside it, showing `sound-on` or `sound-off`. A press is
  `game.commands.mute()` or `unmute()`, and it follows the sound however it was muted (an M key, a settings screen).
  `icon` and `mutedIcon` swap in the game's own pictures; an `onClick` runs after the switch, to save the choice.
- Both take any widget spec (`anchor x y w h style id`), so they move, resize and restyle like any button. They wear
  the `icon` role, which is `default` until a theme makes it a round icon button.
- The icons are [Phosphor Icons](https://phosphoricons.com) (MIT): the pack's `ICONS-LICENSE.md`.

Every data field, with its range and default, is listed once in `format.ts` (`UI_STYLE_FIELDS`); the shader reads the same fields.

Built-ins: the look a game has before it chooses a skin is the candy skin's (`ui-skin-candy`), drawn in the engine's
bold sans rather than candy's display face, so it loads no font of its own: `default` a yellow pill with a white rim, a
jelly gloss, a passing shine and a lip it presses into; `good warn bad` and the colour buttons `green red blue yellow
orange purple pink teal grey brown` the same pill in other colours; `flat` a grey one; `dark` a purple window. The roles
a theme restyles: `panel` (a plain panel; panels use it by default), `icon` (the pause and sound buttons), `label`
(labels use it by default), `heading`, `title` (a window's title bar). The parts: `track knob fill` (slider, progress),
`box tick dot` (checkbox, radio), `field focus` (text), `row rowSelected` (lists), `scrollTrack scrollThumb`. And two
of the engine's own, `glass` and `retro`. `UI_ROLES` lists every role with what it is. Under a theme, a role it does
not name falls back to the built-in, but a window shows a title bar only when the theme (or the game, with
`defineStyle`) has a `title`. Compose `ui-skin-candy` and choose `'candy'` for the same look in its Luckiest Guy
captions, as `bake new` games do; `UI_DEFAULT_STYLES` is the built-in set as data.

### Theme files

A whole interface skin is one JSON file, `phaser-ae-ui-theme` — every role's style, the fonts it needs, and the dialogue box that matches it:

```json
{
  "format": "phaser-ae-ui-theme",
  "version": 1,
  "name": "crypt",
  "font": "17px Lora",
  "fonts": [
    {
      "family": "Cinzel",
      "url": "https://cdn.phaser.games/gameblocks/fonts/cinzel-aa481f2117ec0bca8294.glb"
    }
  ],
  "styles": {
    "default": {
      "fill": "#4a161c",
      "fillTo": "#1c0a0c",
      "corner": "cut",
      "radius": 10,
      "border": 2,
      "borderColor": "#c9a063",
      "ring": 1,
      "ringInset": 5,
      "font": "bold 17px Cinzel",
      "textCase": "upper",
      "letterSpacing": 1.5,
      "hover": { "shadow": 0.9, "shadowColor": "#c0392b", "shadowY": 0 }
    },
    "dark": {
      "fill": "#140d10",
      "corner": "scoop",
      "radius": 18,
      "pattern": "grain",
      "patternColor": "#ffffff10",
      "patternScale": 3
    }
  },
  "dialogue": {
    "ink": "#e8dcc8",
    "nameInk": "#e8c98a",
    "accent": "#c9a063",
    "motif": "gold",
    "font": "24px Lora",
    "panel": { "fill": "#140d10f0", "corner": "scoop", "radius": 16 }
  }
}
```

```ts
game.ui.theme = await game.ui.loadTheme("assets/ui/crypt.json"); // the asset loader: a pack's base URL applies
```

`loadTheme(url | object)` reads the file leniently (a bad value is dropped, numbers clamped to the catalogue's ranges), loads and registers its `fonts` (baked Typography GLBs — the CDN font catalogue), defines the theme and returns its name; it does not switch to it. `defineTheme(def)` at runtime REPLACES a theme of the same name, live, so an editor can restyle a running game. `themeDef` is the active theme's definition. The `dialogue` section is read by the dialogue pack: a dialogue opened without a preset wears it. `parseUiTheme`, `serializeUiTheme`, `UI_STYLE_FIELDS` and `UI_ROLES` are exported, pure, for tools that write themes.

### Scoped widget parts

Pass `roles` to a widget, or replace `h.ui.roles` live, to style its auxiliary parts without changing other widgets or the active theme:

```ts
const slider = game.ui.slider({
  style: "track",
  roles: { fill: { fill: "#6fb6ff" }, knob: { base: "flat", radius: 3 } },
});
slider.ui.roles = { fill: "good", knob: "flat" };
```

Supported parts are `fill`, `knob`, `tick`, `dot`, and `track` (slider/toggle groove or scroll track). Each accepts a named style or normal style data including state overrides. Checkbox marks use an analytic two-segment check shape; `tick` controls their material. Themes without explicit disabled styling receive a muted tint and label; explicit disabled overrides win. Default toggles use the fill role when on and the track role when off. Changing `disabled` repaints existing labels as well as changing interaction state.

## Options

None.

### Modals

```ts
const dialog = game.ui.window({ w: 300, h: 140, title: "Delete the save?" });
game.ui.button({
  parent: dialog,
  x: 20,
  y: 80,
  text: "Delete",
  onClick: () => {
    doIt();
    game.ui.modal(dialog, false);
  },
});
game.ui.modal(dialog);
```

A modal is not a second surface and not a stencil: it is a **z band**. `modal(h)` raises the
widget and everything under it by a band no ordinary widget reaches, so it stacks wholly above
what is already on screen while keeping its own internal order, and it gates the hit test to
the top modal, so the page beneath takes no hover, no click, no wheel and no scrollbar drag. That second half is
the one a game usually forgets, and the one that turns a dialog into a trap.

Modals stack — the newest takes input. `modal(h, false)` drops one and restacks the rest;
`modalTop` is the one taking input; killing the widget drops it too. A game may kill a modal's widgets with
`roster.kill` while it is up (tearing down a pause screen, with or without a dialog stacked on it): the next frame
forgets them and restacks what is left.

## Limits

- Flex row/column layout only: no wrapping, no grid, no percentage sizes; a widget's `w h` are pixels (or stretched by `align: 'stretch'`).
- Fonts must cover the characters used. Supply a loaded fallback stack for additional scripts.
- `textOutline` is clamped to what the font's distance field holds: about 1/20 of the font size, less half a screen pixel. A thicker outline needs a larger font, or a font baked with a larger `pixelRange`.
- One pointer and one keyboard/controller focus. Browser text entry uses engine-owned native inputs/textareas for selection, clipboard, composition and mobile keyboards. The focused editor uses the browser's system font and selection rendering; GPU labels continue to use Typography. Headless editing preserves grapheme boundaries but cannot test a real OS keyboard or IME.
- Widgets are screen-space by default; in a world layer they sort and scroll like sprites but still read the pointer in screen px.
- A `textStroke` wider than the font's distance field reaches (about 1/20 of the size) is the caption drawn again 9 to 33
  times round a ring, and `textDepth` as many again: cheap for buttons and headings, shaped once per change; a label
  rewritten every frame with a wide stroke shapes that many copies each time. A stroke colour with alpha below 1
  darkens where the copies overlap.
- Textures come from packs (`ui-texture-wood`, `ui-texture-paper`, `ui-texture-stone`), generated at startup, or from
  the game's own pictures; nothing is bundled into this pack. A picture in a texture of its own (one too big for the
  atlas) splits the panel draw where it is used. The atlas has no mipmaps, so a texture drawn much smaller than its
  pixels shimmers in motion: keep `textureScale` near the picture's size.
- The lip is drawn inside the widget's box: a 60 px button with `depth: 8` has a 52 px face. Every material effect is
  computed per pixel in the one panel draw; a menu's worth costs nothing measurable, a thousand full-screen panels would.

### Bounded read-only text

Text fields accept `readOnly: true` to prevent editing while keeping their normal appearance.
`textAlign: 'left' | 'center' | 'right'` aligns lines inside the field. A textarea with
`textOverflow: 'hidden'` clips at its fixed top position and ignores wheel scrolling;
the default `'scroll'` retains scrolling. These properties are live on `widget.ui`.
`widget.ui.placeholder` updates an empty field's hint and repaints it without changing its value.

## Keyboard, controller and accessible input

Interactive widgets share one focus: Tab/Shift+Tab follow `tabIndex` (default creation order; negative excludes), arrow keys use spatial neighbours, and `neighbours: { right: 'next-id' }` overrides a direction. Enter/Space activate buttons, toggles and radios. Arrows adjust sliders and list/dropdown selection. `game.ui.navigate('next')` and `widget.ui.focused = true` expose the same behavior. Focus has a visible gold border. Standard gamepads use Start to enter menu navigation, D-pad/left stick to move, A to activate and B to leave focus; release the control before moving again.

Modals trap navigation in their subtree, make other browser controls inert, and restore prior live focus on close. Hidden, disabled, killed and suspended-scene controls cannot receive input. Text focus, modals and controller menu navigation capture world input through the kernel, including rig polling. Ordinary button focus claims navigation keys without disabling unrelated movement. Escape leaves focus; a modal still captures until closed through `modal(h, false)`.

The engine owns the browser controls and removes them on disposal. Supply `accessibleLabel` when visible text is not a useful control name. Text fields use native selection, clipboard, IME and mobile keyboard behavior; no game-authored DOM is needed. Root widgets use the safe rectangle by default; `safeArea: false` is appropriate for full-bleed decoration. An agent should still check the target screen reader and physical phone keyboard: headless and synthetic events do not certify them.

## Typography font selection

The bundled pack supplies sans, serif and monospace families in regular and bold.
`style.font` selects a logical size and family, for example `"bold 18px monospace"`.
Registered Typography family names can also be used. A font descriptor does not load
an operating-system font; load source fonts or baked font assets through Typography.

```ts
await game.ui.ready();
const latin = await game.typography.load("/fonts/latin.glb");
const arabic = await game.typography.load("/fonts/arabic.glb");
game.ui.font = game.typography.stack(latin, arabic);
game.ui.button({ text: "ابدأ", style: { font: "20px sans-serif" } });
```

`game.ui.font` sets the default loaded font or fallback stack (from `load` and `stack`, or a face's `font` once
`await face.ready` has resolved). `null` restores the
style-selected family. `style.textFont` overrides the selection for one widget.
Changing fonts updates existing captions, field wrapping and container layout.
For text entry in additional scripts, load a Typography font stack containing those glyphs. The native editor's system-font fallback does not add glyphs to the GPU font stack used after the field loses focus.
Visible lines reuse their Typography objects; clipping intersects the field interior
with every clipping ancestor. Hidden widgets and scene deletion retain the same ownership rules.
